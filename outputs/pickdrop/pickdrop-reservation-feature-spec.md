## 1. 개요

픽드랍 예약은 일반 서비스 예약 또는 호텔링 예약에 픽업/하원 이동 서비스를 함께 예약하고, 선택한 이동 옵션에 따라 금액과 이용권 차감을 반영하는 기능이다.

### Business Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| B-P | 기능 범위 | 픽드랍은 단독 목록 조회, 일반 예약 등록 중 추가 예약, 기존 예약 상세/수정, 호텔링 예약 연계에서 동작한다. |
| B-1 | 이동 유형 | 픽업만 선택하거나 하원만 선택하면 편도 예약으로 처리한다. 픽업과 하원을 모두 선택하면 왕복 예약으로 처리한다. |
| B-2 | 금액 반영 | 픽드랍 금액은 일반 서비스 금액 또는 호텔링 금액과 구분해 계산하되, 최종 결제 합계에는 함께 반영한다. |
| B-3 | 이용권 반영 | 픽드랍 이용권은 일반 서비스 이용권과 별도로 선택하고 차감한다. |

### UI Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| U-P | 화면 범위 | 관리자는 픽드랍 목록, 예약 등록 모달, 예약 상세, 호텔링 예약 화면에서 픽드랍 정보를 확인하거나 수정할 수 있다. |
| U-1 | 표시 단위 | 화면에서는 픽업, 하원, 왕복 여부와 선택 날짜, 금액, 이용권 사용 정보를 구분해 보여준다. |

### Integration Notes

| No. | 연결 | 명세 |
| --- | --- | --- |
| I-1 | 옵션 선택 -> 금액/이용권 | 픽업 또는 하원 선택 상태가 바뀌면 금액 계산과 이용권 차감 대상도 함께 갱신되어야 한다. |

## 2. 공통 정책

### Business Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| B-P | 선택 없음 | 픽업과 하원을 모두 선택하지 않으면 픽드랍 금액과 픽드랍 이용권 차감은 발생하지 않는다. |
| B-1 | 편도 | 픽업 또는 하원 중 하나만 선택한 날짜는 편도 기준으로 계산한다. |
| B-2 | 왕복 | 픽업과 하원을 모두 선택한 날짜는 왕복 기준으로 계산한다. |
| B-3 | 날짜 기준 | 픽드랍 날짜는 일반 서비스 예약 날짜와 별도로 관리할 수 있다. |
| B-4 | 기본 날짜 | 픽드랍 모드에 처음 진입하면 기존에 선택된 서비스 예약 날짜를 픽드랍 날짜의 기본값으로 사용할 수 있다. |
| B-5 | 직접 변경 우선 | 사용자가 픽드랍 날짜를 직접 변경한 뒤에는 일반 서비스 날짜 변경이 픽드랍 날짜를 임의로 덮어쓰지 않아야 한다. |

### UI Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| U-P | 옵션 표시 | 픽업과 하원 옵션은 각각 독립적으로 선택할 수 있어야 한다. |
| U-1 | 기본 선택 | 픽드랍 모드 진입 시 선택 가능한 날짜 범위 안에서 기본 날짜가 표시된다. |
| U-2 | 날짜 초과 | 선택 가능한 픽드랍 가능 횟수보다 기본 선택 날짜가 많으면 가능한 범위까지만 선택된다. |
| U-3 | 빈 상태 | 픽드랍 이용권이 없거나 사용 가능 횟수가 없으면 이용권 영역은 빈 상태 또는 사용 불가 상태를 보여준다. |

### Integration Notes

| No. | 연결 | 명세 |
| --- | --- | --- |
| I-1 | 날짜 선택 -> 이용권 | 픽드랍 날짜가 변경되면 날짜별 필요한 이용권 차감 수량도 다시 계산한다. |
| I-2 | 옵션 선택 -> 저장 가능 여부 | 픽업/하원 옵션과 날짜가 모두 저장 가능한 상태인지 확인한 뒤 예약 저장을 허용한다. |

## 4. 일반 예약 등록 중 픽드랍 모드

### Context

| Field | Value |
| --- | --- |
| 상황 | 관리자가 일반 서비스 예약을 등록하다가 픽드랍 예약을 함께 추가한다. |
| 화면명 | 예약 등록 모달 |
| 경로 | 예약 관리 > 예약 등록 > 픽드랍 추가 |
| Case | 일반 예약과 픽드랍 예약 동시 저장 |

### Business Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| B-P | 모드 전환 | 픽드랍 모드로 전환해도 기존에 선택한 회원, 서비스, 일반 예약 날짜는 유지한다. |
| B-1 | 저장 분기 | 일반 예약만 저장하는 경우와 픽드랍까지 포함해 저장하는 경우를 구분한다. |
| B-2 | 동시 저장 | 일반 예약 날짜와 픽드랍 날짜가 겹치면 같은 날짜의 예약 정보에 픽드랍 정보를 함께 저장한다. |
| B-3 | 별도 저장 | 픽드랍 날짜가 일반 예약 날짜에 포함되지 않으면 픽드랍 전용 예약 정보를 별도로 추가한다. |

### UI Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| U-P | 진행 단계 | 픽드랍 모드에서는 일반 예약 단계와 픽드랍 단계가 구분되어 보여야 한다. |
| U-1 | 진입 버튼 | 서비스 날짜가 선택된 경우 버튼 문구는 픽드랍까지 함께 예약하는 흐름임을 보여준다. |
| U-2 | 표시 영역 | 픽드랍 모드에서는 픽드랍 금액 영역과 픽드랍 이용권 영역을 표시한다. |
| U-3 | 모드 해제 | 저장 완료, 모달 종료, 이전 단계 이동 시 픽드랍 모드는 초기화된다. |

### Integration Notes

| No. | 연결 | 명세 |
| --- | --- | --- |
| I-1 | 픽드랍 모드 진입 -> 기존 예약 상태 유지 | 화면은 픽드랍 입력 상태로 바뀌지만 일반 예약에 필요한 기존 선택값은 유지되어야 한다. |
| I-2 | 저장 버튼 -> 저장 분기 | 사용자가 어떤 저장 버튼을 선택했는지에 따라 일반 예약만 저장할지 픽드랍까지 저장할지 결정한다. |

## 7. 이용권 차감

### Business Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| B-P | 이용권 구분 | 픽드랍 이용권은 일반 서비스 이용권과 별도로 관리한다. |
| B-1 | 편도 차감 | 편도 예약은 편도 이용권 1회를 우선 차감한다. |
| B-2 | 왕복 차감 | 왕복 예약은 왕복 이용권 1회를 우선 차감한다. |
| B-3 | 대체 차감 | 왕복 이용권이 부족한 경우 편도 이용권 2회로 대체할 수 있는지 정책 확정이 필요하다. |
| B-4 | 날짜별 차감 | 여러 날짜를 선택하면 날짜별로 필요한 이용권 수량을 계산한다. |
| B-5 | 부족 상태 | 사용 가능한 이용권이 부족하면 저장 차단 또는 초과 예약 허용 여부를 정책에 따라 처리한다. |

| U-2 | 부족 안내 | 이용권이 부족하면 부족 상태를 명확히 표시한다. |
| U-3 | 빈 상태 | 사용할 수 있는 픽드랍 이용권이 없으면 빈 상태를 표시한다. |

## 8. 저장 정책

### Business Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| B-P | 저장 단위 | 일반 예약 정보와 픽드랍 예약 정보는 같은 저장 흐름 안에서 처리될 수 있다. |
| B-1 | 겹치는 날짜 | 일반 예약 날짜와 픽드랍 날짜가 같으면 같은 날짜 예약에 픽업/하원 정보를 함께 저장한다. |
| B-2 | 독립 날짜 | 픽드랍 날짜가 일반 예약 날짜와 다르면 픽드랍 전용 예약으로 추가한다. |
| B-3 | 이용권 이력 | 일반 서비스 이용권 사용 이력과 픽드랍 이용권 사용 이력은 같은 날짜 예약 안에서도 구분되어야 한다. |
| B-4 | 저장 실패 | 필수 선택 누락, 이용권 부족, 정책상 허용되지 않는 초과 상태에서는 저장을 차단하고 사용자에게 사유를 알려야 한다. |

### UI Logic

| No. | 항목 | 명세 |
| --- | --- | --- |
| U-P | 저장 버튼 | 일반 예약만 저장하는 버튼과 픽드랍까지 포함해 저장하는 버튼의 의미가 구분되어야 한다. |
| U-1 | 저장 완료 | 저장이 완료되면 모달 상태를 초기화하고 목록 또는 상세에 최신 정보를 반영한다. |

## 12. Open Questions

### Product Policy

- 픽드랍 이용권이 부족한 상태에서 저장을 차단할지, 초과 예약으로 허용할지 결정이 필요하다.
- 호텔링에서 체크인 픽업과 체크아웃 하원을 모두 선택한 경우 왕복 이용권 1회로 볼지, 편도 이용권 2회로 볼지 결정이 필요하다.
- 가격 정보가 없는 픽드랍 옵션을 저장 가능하게 둘지, 금액 설정 전까지 차단할지 결정이 필요하다.

### UX Copy

- 픽업만 선택한 편도와 하원만 선택한 편도를 화면에서 같은 "편도"로 표시할지, "픽업 편도"와 "하원 편도"로 구분할지 결정이 필요하다.
- 이용권 부족 상태의 안내 문구와 저장 차단 문구를 확정해야 한다.

### Operations

- 기존 예약의 픽드랍 이용권 이력이 현재 사용 가능 후보와 맞지 않는 경우 자동 보정할지, 관리자 확인 후 수정하게 할지 결정이 필요하다.
