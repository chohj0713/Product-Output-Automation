## C-01. 픽드랍 옵션 선택

### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 유치원 또는 호텔링 예약을 등록/수정하면서 픽업·드랍 여부를 지정한다. |
| 화면명 | 예약 등록/수정 모달 |
| 경로 | 유치원 예약 또는 호텔링 예약 등록/수정 플로우 |
| 사용자 목표 | 상위 예약에 종속된 픽드랍 부가 서비스를 선택한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 선택 정책 | 픽드랍은 독립 예약이 아니라 유치원/호텔링 예약에 종속된 부가 서비스다. | 예약 플로우 안에서 픽업/드랍 선택을 제공한다. | 상위 예약 없이 픽드랍만 완전히 독립된 예약으로 생성하지 않는다. | 상위 예약의 날짜 entry 안에 픽드랍 선택 상태를 저장한다. |
| 1 | 픽업 선택 | 픽업만 선택할 수 있다. | `픽업` 옵션을 선택 상태로 표시한다. | 시간, 장소, 메모가 비어 있어도 선택 가능하다. | 대상 날짜 entry에 픽업 사용 상태를 반영한다. |
| 2 | 드랍 선택 | 드랍만 선택할 수 있다. | `드랍` 옵션을 선택 상태로 표시한다. | 시간, 장소, 메모가 비어 있어도 선택 가능하다. | 대상 날짜 entry에 드랍 사용 상태를 반영한다. |
| 3 | 동시 선택 | 픽업과 드랍은 동시에 선택할 수 있다. | 두 옵션을 동시에 선택 상태로 표시한다. | 동시 선택을 중복 예약으로 보지 않는다. | 동일 예약 하위에 픽업과 드랍 상태를 함께 저장한다. |
| 4 | 미선택 | 픽업/드랍을 모두 선택하지 않을 수 있다. | 두 옵션 모두 미선택 상태로 둔다. | 미선택이어도 상위 예약 등록은 가능하다. | 픽드랍 이용권 차감은 발생하지 않는다. |

## C-02. 픽드랍 입력값 유지

### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 픽업/드랍의 시간, 장소, 메모를 입력하거나 선택을 해제한다. |
| 화면명 | 예약 등록/수정 모달 |
| 경로 | 픽드랍 선택 후 세부 입력 영역 |
| 사용자 목표 | 픽드랍에 필요한 부가 정보를 선택적으로 입력한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 입력 정책 | 픽업/드랍의 시간, 장소, 메모는 모두 optional이다. | 입력란은 비어 있어도 저장 가능해야 한다. | 필수값 누락 validation을 발생시키지 않는다. | 빈 값은 빈 값 또는 미입력 상태로 저장한다. |
| 1 | Placeholder | 픽드랍 입력란에는 별도 placeholder를 제공하지 않는다. | 입력란은 placeholder 없이 표시한다. | 안내 문구로 필수 입력처럼 오해시키지 않는다. | 데이터 영향 없음. |
| 2 | 선택 해제 | 픽업/드랍 선택을 해제해도 기존 시간/장소/메모 값은 삭제하지 않는다. | 선택 해제 시 해당 입력값은 화면에서 숨기거나 비활성 상태로 보인다. | hidden 값은 저장 전 상태에서 유지된다. | 기존 입력값은 내부 상태에 유지된다. |
| 3 | 재선택 | 선택 해제 후 다시 선택하면 기존 값을 복원한다. | 재선택 시 이전에 입력했던 시간/장소/메모를 다시 표시한다. | 사용자가 직접 지운 값은 복원 대상이 아니다. | 유지 중인 hidden 값을 다시 활성 입력값으로 사용한다. |
| 4 | 시간 충돌 | 픽드랍 시간이 예약 시작/종료 시간과 충돌해도 검사하지 않는다. | 경고나 저장 차단 없이 그대로 둔다. | 운영자가 입력값을 자체 판단한다. | 충돌 여부를 별도 필드로 저장하지 않는다. |

## C-03. 예약 날짜/시간 변경 시 픽드랍 처리

### Context

| Field | Value |
| --- | --- |
| 상황 | 기존 예약을 수정하면서 예약 날짜 또는 예약 시간을 변경한다. |
| 화면명 | 예약 수정 모달 |
| 경로 | 기존 예약 상세/목록에서 수정 진입 |
| 사용자 목표 | 예약 변경 시 픽드랍 정보가 예측 가능한 기준으로 유지 또는 초기화되게 한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 변경 기준 | 픽드랍 정보 유지 여부는 예약 날짜 변경 여부를 기준으로 판단한다. | 날짜 변경과 시간 변경 결과에 따라 픽드랍 상태를 동기화한다. | 단순 시간 변경은 픽드랍 초기화 사유가 아니다. | 날짜 변경 시 픽드랍 선택/입력/이용권 계획을 초기화한다. |

| 2 | 시간만 변경 | 예약 시간이 변경되면 기존 픽드랍 정보는 유지된다. | 픽업/드랍 선택과 입력값을 그대로 보여준다. | 시간 충돌 검사는 하지 않는다. | 기존 픽드랍 flag, 입력값, 이용권 계획을 유지한다. |
| 3 | 날짜+시간 변경 | 날짜가 함께 변경되면 시간 변경 여부와 무관하게 초기화한다. | 새 날짜 기준으로 미선택 또는 기본 상태를 표시한다. | 날짜 변경 초기화 정책이 우선한다. | 기존 날짜에 연결된 픽드랍 데이터와 이용권 계획은 제거 또는 재계산 대상이 된다. |

## C-04. 픽드랍 예약 저장

### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 유치원/호텔링 예약과 함께 픽드랍 정보를 저장한다. |
| 화면명 | 예약 등록/수정 모달 |
| 경로 | 예약 저장 또는 픽드랍까지 예약 액션 |
| 사용자 목표 | 선택한 픽드랍 정보를 상위 예약과 함께 저장한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 저장 단위 | 픽드랍은 상위 예약의 날짜 entry 단위로 저장된다. | 저장 완료 후 예약 목록/상세에서 픽드랍 예약 여부가 확인되어야 한다. | 상위 예약 저장 실패 시 픽드랍도 저장되지 않는다. | 예약 entry에 픽업/드랍 상태와 관련 이용권 사용 내역을 반영한다. |
| 1 | 유치원+픽드랍 저장 | 유치원 예약 날짜에 픽드랍 정보를 연결한다. | 유치원 예약 플로우에서 픽드랍까지 예약할 수 있다. | 유치원 예약 필수 조건은 상위 예약 기준을 따른다. | 유치원 예약 데이터에 픽드랍 하위 서비스 정보가 추가된다. |
| 2 | 호텔링+픽드랍 저장 | 호텔링 입실/퇴실 날짜 entry에 픽드랍 정보를 연결한다. | 호텔링 예약 플로우에서 픽드랍까지 예약할 수 있다. | 호텔링 예약의 숙박 날짜 정책을 우선 적용한다. | 호텔링 예약 데이터에 픽드랍 하위 서비스 정보가 추가된다. |
| 3 | 액션 문구 | 선택 날짜가 없으면 `픽드랍만 예약`, 선택 날짜가 있으면 `픽드랍까지 예약` 맥락으로 액션을 구분한다. | 현재 선택 상태에 맞는 저장/진입 버튼 문구를 보여준다. | 픽드랍만 예약도 독립 예약이 아니라 상위 예약 구조 안의 부가 서비스로 저장한다. | 상위 예약 구조 안에 픽드랍 정보가 저장된다. |

## C-05. 픽드랍 예약 수정/취소

| 화면명 | 예약 상세/수정 모달 |
| 경로 | 예약 목록/상세에서 수정 또는 취소 |
| 사용자 목표 | 픽드랍이 상위 예약 상태와 동일한 기준으로 처리되게 한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 종속 정책 | 픽드랍은 유치원/호텔링 예약에 종속된 부가 서비스이며 상위 예약 상태를 따른다. | 픽드랍을 별도 상태로 분리하지 않는다. | 픽드랍만 독립 취소/완료 상태로 관리하지 않는다. | 상위 예약 상태 변경이 픽드랍에도 적용된다. |

## C-06. 픽드랍 이용권 차감

### Context

| Field | Value |
| --- | --- |
| 상황 | 픽드랍을 선택한 예약에 픽드랍 타입 이용권을 적용한다. |
| 화면명 | 예약 등록/수정 모달의 이용권 영역 |
| 경로 | 픽드랍 선택 후 결제/이용권 영역 |
| 사용자 목표 | 픽드랍 예약에 맞는 이용권만 정확히 차감한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 이용권 범위 | 픽드랍은 픽드랍 타입 이용권에만 영향을 준다. | 픽드랍 이용권 섹션을 일반 예약 이용권과 구분해 표시한다. | 일반 유치원/호텔링 이용권 차감 횟수에는 영향을 주지 않는다. | 픽드랍 타입 이용권의 사용 내역만 추가/변경한다. |
| 1 | 부가요금 | 픽드랍은 별도 부가요금에 영향을 주지 않는다. | 픽드랍 요금이 있더라도 총 금액에 별도 과금으로 반영하지 않는다. | 현장 결제나 할인과 연결하지 않는다. | 결제 금액 데이터에는 픽드랍 부가요금을 추가하지 않는다. |
| 2 | 편도 이용권 | 사용한 이용권이 편도이면 픽업과 드랍을 각각 차감한다. | 픽업만 선택하면 1회, 드랍만 선택하면 1회, 둘 다 선택하면 2회 사용 결과를 보여준다. | 잔여 회차가 부족하면 상위 이용권 초과 정책을 따른다. | 날짜별 픽드랍 사용 내역에 편도 이용권 사용 횟수를 기록한다. |
| 3 | 왕복 이용권 | 사용한 이용권이 왕복이면 픽업/드랍 선택 조합과 무관하게 해당 날짜에 1회 차감한다. | 픽업만, 드랍만, 픽업+드랍 모두 1회 사용 결과를 보여준다. | 왕복 이용권을 편도 2회로 쪼개 저장하지 않는다. | 날짜별 픽드랍 사용 내역에 왕복 이용권 1회 사용을 기록한다. |
| 4 | 왕복 우선 | 픽업+드랍은 왕복 이용권을 우선 적용하고, 왕복이 없으면 편도 2회로 대체한다. | 선택된 이용권의 잔여 회차 전후 값을 표시한다. | 편도만 있는 경우 픽업+드랍은 편도 2회가 필요하다. | 선택 순서와 잔여 회차 기준으로 이용권 사용 계획을 생성한다. |
| 5 | 편도 fallback | 픽업 또는 드랍 하나만 선택한 경우 편도 이용권을 우선 적용하고, 편도가 없으면 왕복 1회를 사용할 수 있다. | 적용된 이용권 기준으로 잔여 회차를 표시한다. | 왕복으로 편도 사용해도 1회 차감한다. | 픽드랍 사용 내역에 실제 사용된 이용권 ID와 회차를 기록한다. |

## C-08. 범위 제외 정책

### Context

| Field | Value |

| 화면명 | 관리자 예약 화면 |
| 경로 | 기능명세 범위 정의 |
| 사용자 목표 | 현재 구현/명세 범위를 명확히 제한한다. |

### Integrated Logic

| No. | 항목 | Business Logic | UI Logic | 예외/제약 | 저장/데이터 영향 |
| --- | --- | --- | --- | --- | --- |
| P | 범위 기준 | 현재 명세는 관리자 예약 등록/수정/조회에서의 픽드랍을 대상으로 한다. | 관리자 화면 기준으로만 UI 동작을 정의한다. | 보호자용 화면과 알림은 별도 명세에서 다룬다. | 범위 밖 데이터 구조를 새로 정의하지 않는다. |

## Global Assumptions

- 최종 기능명세에는 코드 근거, 파일 경로, 함수명, 내부 커버리지 ID를 표시하지 않는다.
- 내부 커버리지 검증은 `logic-inventory.md`와 `coverage-matrix.md`에서만 관리한다.
- 케이스 계획은 `case-plan.md`에서만 관리한다.
- 확인이 필요한 정책/UX/운영 질문은 `open-questions.md`에서만 관리한다.
