## Biz Web / 예약 관리

### 예약 등록/수정 모달

#### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 유치원 또는 호텔링 예약을 등록/수정하면서 픽업·드랍 부가 서비스를 함께 설정한다. |
| 화면명 | 예약 등록/수정 모달 |
| 경로 | 예약 관리 > 예약 등록 또는 예약 상세 > 수정 |
| Case | C-01 옵션 선택, C-02 입력값 유지, C-03 날짜/시간 변경, C-04 저장 |
| 사용자 목표 | 상위 예약 흐름 안에서 픽드랍 여부와 이용 날짜를 선택하고 저장한다. |

#### Policy

| No. | Policy | Detail |
| --- | --- | --- |
| P | 종속 서비스 정책 | 픽드랍은 독립 예약이 아니라 유치원/호텔링 예약에 종속된 부가 서비스로 저장한다. |
| P | 선택 허용 정책 | 픽업만, 드랍만, 픽업+드랍, 미선택을 모두 허용한다. |
| P | 입력 optional 정책 | 픽드랍 시간, 장소, 메모는 필수값이 아니며 비어 있어도 저장 가능하다. |
| P | 날짜 변경 정책 | 기존 예약 수정 중 예약 날짜가 변경되면 기존 픽드랍 선택값과 이용권 계획을 새 날짜 기준으로 초기화 또는 재산정한다. 시간만 변경되면 픽드랍 정보는 유지한다. |

#### UI Callouts

| No. | Type | 항목 | Policy / Business Logic | UX / UI Behavior | Exception / Constraint | Data / State Impact |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Option | 픽업 선택 | 픽업은 단독 선택 가능하다. | 픽업 옵션을 선택 상태로 표시한다. | 시간, 장소, 메모가 없어도 선택 가능하다. | 대상 날짜 entry에 픽업 상태를 저장한다. |
| 2 | Option | 드랍 선택 | 드랍은 단독 선택 가능하다. | 드랍 옵션을 선택 상태로 표시한다. | 시간, 장소, 메모가 없어도 선택 가능하다. | 대상 날짜 entry에 드랍 상태를 저장한다. |
| 3 | Option | 픽업+드랍 동시 선택 | 픽업과 드랍은 같은 날짜에 함께 선택할 수 있다. | 두 옵션을 동시에 선택 상태로 보여준다. | 동시 선택을 중복 예약으로 보지 않는다. | 동일 날짜 entry에 픽업/드랍 상태를 함께 저장한다. |
| 4 | Option | 미선택 | 픽업/드랍을 모두 선택하지 않아도 상위 예약은 저장 가능하다. | 두 옵션 모두 미선택 상태로 둔다. | 픽드랍 미선택 시 픽드랍 이용권 차감은 발생하지 않는다. | 픽드랍 관련 flag와 사용 내역을 만들지 않는다. |
| 5 | Input | 시간/장소/메모 | 픽드랍 세부 입력값은 모두 optional이다. | 입력란은 비어 있어도 오류를 표시하지 않는다. | 필수 입력처럼 보이는 placeholder 또는 validation을 제공하지 않는다. | 빈 값은 미입력 상태로 저장한다. |
| 6 | Option | 선택 해제 후 재선택 | 선택 해제해도 입력 중이던 시간/장소/메모는 즉시 삭제하지 않는다. | 해제 시 입력 영역을 숨기거나 비활성화하고, 재선택 시 기존 값을 복원한다. | 사용자가 직접 지운 값은 복원하지 않는다. | 저장 전 내부 상태에 hidden 값을 유지한다. |
| 7 | DatePicker | 예약 날짜 변경 | 날짜 변경은 픽드랍 정보 초기화 기준이다. | 새 날짜 기준으로 픽업/드랍을 다시 설정하게 한다. | 기존 날짜의 hidden 값은 새 날짜에 자동 복원하지 않는다. | 픽드랍 flag, 입력값, 이용권 사용 계획을 새 날짜 기준으로 재산정한다. |
| 8 | Input | 예약 시간 변경 | 시간만 변경하면 기존 픽드랍 정보는 유지한다. | 픽업/드랍 선택과 입력값을 그대로 표시한다. | 예약 시간과 픽드랍 시간 충돌은 검사하지 않는다. | 기존 픽드랍 flag와 이용권 계획을 유지한다. |
| 9 | Button | 픽드랍까지 예약 / 픽드랍만 예약 | 선택 날짜가 있으면 상위 예약과 픽드랍을 함께 저장하고, 선택 날짜가 없으면 픽드랍 중심 저장 맥락으로 진입한다. | 현재 선택 상태에 맞는 버튼 문구를 보여준다. | 픽드랍만 예약도 별도 독립 예약이 아니라 상위 예약 구조 안의 부가 서비스로 저장한다. | 상위 예약의 날짜 entry에 픽드랍 정보를 연결한다. |

## Biz Web / 예약 관리

### 픽드랍 이용권 영역

#### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 픽드랍 예약에 사용할 이용권을 확인하거나 선택한다. |
| 화면명 | 예약 등록/수정 모달의 이용권 영역 |
| 경로 | 예약 관리 > 예약 등록/수정 > 픽드랍 선택 후 이용권 영역 |
| Case | C-06 픽드랍 이용권 차감 |
| 사용자 목표 | 픽드랍 예약에 맞는 이용권만 정확히 차감한다. |

#### Policy

| No. | Policy | Detail |
| --- | --- | --- |
| P | 이용권 분리 정책 | 픽드랍은 픽드랍 타입 이용권에만 영향을 주며 일반 유치원/호텔링 이용권 차감 횟수에는 영향을 주지 않는다. |
| P | 부가요금 제외 정책 | 픽드랍은 별도 부가요금이나 현장 결제 금액에 영향을 주지 않는다. |
| P | 편도 차감 정책 | 편도 이용권은 픽업과 드랍을 각각 1회로 차감한다. |
| P | 왕복 차감 정책 | 왕복 이용권은 픽업/드랍 선택 조합과 무관하게 해당 날짜에 1회 차감한다. |
| P | 차감 우선순위 | 픽업+드랍은 왕복 1회를 우선 적용하고, 왕복이 없으면 편도 2회로 대체한다. 픽업 또는 드랍 하나만 선택한 경우 편도 1회를 우선 적용하고, 편도가 없으면 왕복 1회를 사용할 수 있다. |

#### UI Callouts

| No. | Type | 항목 | Policy / Business Logic | UX / UI Behavior | Exception / Constraint | Data / State Impact |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Section | 픽드랍 이용권 섹션 | 픽드랍 타입 이용권만 후보로 사용한다. | 일반 예약 이용권 영역과 구분해서 표시한다. | 사용 가능한 픽드랍 이용권이 없으면 빈 상태를 표시한다. | 픽드랍 타입 이용권 사용 내역만 생성/변경한다. |
| 2 | Text | 잔여 회차 표시 | 선택한 이용권 기준으로 차감 전/후 잔여 회차를 계산한다. | 이용권 row에 사용 전후 값을 표시한다. | 잔여 회차가 부족하면 상위 이용권 초과 정책을 따른다. | 날짜별 픽드랍 이용권 사용 계획을 만든다. |
| 3 | Option | 편도 이용권 | 픽업만 또는 드랍만 선택하면 편도 1회를 우선 차감한다. | 편도 이용권이 적용된 사용 결과를 보여준다. | 편도 이용권이 없으면 왕복 1회를 사용할 수 있다. | 실제 사용된 이용권 ID와 1회 차감 내역을 저장한다. |
| 4 | Option | 왕복 이용권 | 픽업+드랍은 왕복 1회를 우선 차감한다. | 왕복 이용권이 적용된 사용 결과를 보여준다. | 왕복 이용권이 없으면 편도 2회로 대체한다. | 왕복 이용권은 편도 2회로 쪼개 저장하지 않는다. |
| 5 | Section | 결제 금액 | 픽드랍 선택은 별도 부가요금에 영향을 주지 않는다. | 총 결제 금액에는 픽드랍 별도 과금을 반영하지 않는다. | 현장 결제나 할인 정책과 연결하지 않는다. | 결제 금액 데이터에는 픽드랍 부가요금을 추가하지 않는다. |

## Biz Web / 호텔링 예약

#### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 호텔링 예약에 체크인 픽업 또는 체크아웃 드랍을 함께 설정한다. |
| 화면명 | 호텔링 예약/수정 모달 |
| 경로 | 호텔링 관리 > 호텔링 예약 등록 또는 상세 수정 |
| Case | C-04 저장, C-05 수정/취소, C-06 이용권 차감 |
| 사용자 목표 | 호텔링 일정에 맞는 픽드랍 옵션과 이용권 사용을 함께 저장한다. |

#### Policy

| No. | Policy | Detail |
| --- | --- | --- |
| P | 호텔링 연결 정책 | 호텔링 예약에서는 체크인 날짜에 픽업, 체크아웃 날짜에 드랍을 연결한다. |
| P | 상태 종속 정책 | 픽드랍은 호텔링 예약의 상태를 따르며 별도 취소/완료 상태로 분리하지 않는다. |
| P | 이용권 분리 정책 | 호텔링 이용권과 픽드랍 이용권은 별도로 선택하고 저장한다. |

#### UI Callouts

| No. | Type | 항목 | Policy / Business Logic | UX / UI Behavior | Exception / Constraint | Data / State Impact |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Option | 체크인 픽업 | 픽업 선택 시 호텔링 체크인 날짜 entry에 연결한다. | 호텔링 예약 화면에서 픽업 옵션을 선택 상태로 표시한다. | 체크인 날짜가 없으면 저장 대상이 없다. | 체크인 entry에 픽업 상태와 픽드랍 이용권 사용 내역을 저장한다. |
| 2 | Option | 체크아웃 드랍 | 드랍 선택 시 호텔링 체크아웃 날짜 entry에 연결한다. | 호텔링 예약 화면에서 드랍 옵션을 선택 상태로 표시한다. | 체크아웃 날짜가 없으면 저장 대상이 없다. | 체크아웃 entry에 드랍 상태와 픽드랍 이용권 사용 내역을 저장한다. |
| 3 | Section | 호텔링 이용권/픽드랍 이용권 | 호텔링 이용권과 픽드랍 이용권은 서로 다른 사용 계획을 가진다. | 이용권 영역을 구분해 보여준다. | 한쪽 이용권 선택이 다른 쪽 차감에 영향을 주지 않는다. | 각 날짜 entry에 서비스 이용권과 픽드랍 이용권 사용 내역을 구분해 저장한다. |
| 4 | Button | 호텔링 예약 저장 | 상위 호텔링 예약 저장 성공 시 픽드랍 정보도 함께 저장한다. | 저장 후 호텔링 목록/상세에서 픽드랍 여부를 확인할 수 있어야 한다. | 호텔링 예약 저장 실패 시 픽드랍도 저장되지 않는다. | 호텔링 예약 데이터에 픽드랍 하위 서비스 정보가 추가된다. |

## Biz Web / 예약 목록 및 상세

### 예약 목록/상세

#### Context

| Field | Value |
| --- | --- |
| 상황 | 운영자가 저장된 예약에서 픽드랍 예약 여부를 확인하거나 예약을 취소/완료 처리한다. |
| 화면명 | 예약 목록, 예약 상세 |
| 경로 | 예약 관리 > 목록 또는 상세 |
| Case | C-05 수정/취소, C-07 정보 표시, C-08 범위 제외 |
| 사용자 목표 | 픽업과 드랍이 각각 예약되어 있는지 빠르게 확인하고 상위 예약 상태와 함께 관리한다. |

#### Policy

| No. | Policy | Detail |
| --- | --- | --- |
| P | 표시 범위 정책 | 픽드랍 정보는 예약 목록과 예약 상세에 표시한다. 캘린더 표시, 보호자 알림, 보호자 예약 확인 화면은 이 명세 범위에서 제외한다. |
| P | 상태 종속 정책 | 상위 예약이 취소되면 픽드랍도 함께 취소되고, 상위 예약이 완료되면 픽드랍도 완료된 부가 서비스로 간주한다. |
| P | 변경 이력 제외 정책 | 당일 운영 중 픽드랍 정보가 변경되어도 별도 변경 이력 UI나 감사 로그는 현재 범위에 포함하지 않는다. |
